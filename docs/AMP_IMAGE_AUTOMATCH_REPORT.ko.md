# TONEX ONE 앰프 이미지 자동 매칭 개선 보고서

## 결론

현재의 `Automatic matching`은 실제 Tone Model 메타데이터를 사용하지 않는다. 런타임은 이미지 결정 함수에 Tone Model 이름을 항상 `None`으로 전달하고, 프리셋 이름에 포함된 제한적인 키워드만 검사한다. 따라서 프리셋 19처럼 이름에서 앰프 계열을 추정할 수 없는 경우 `TONEX Black` 기본 이미지로 떨어지며, 검은 UI 배경에서는 이미지가 사라진 것처럼 보인다.

레거시 C 펌웨어도 Tone Model을 자동 판별하지 않았다. 레거시는 각 프리셋에 사용자가 고른 이미지 번호를 NVS에 저장했다. 러스트 이식 과정에서 자동 추론 계층은 추가됐지만, 그 입력인 Tone Model 메타데이터 수집은 아직 구현되지 않았다.

## 현재 동작 경로

1. 프리셋별 수동 이미지 설정이 있으면 그 이미지를 사용한다.
2. Tone Model 이름이 있으면 키워드로 매칭하도록 설계돼 있지만, 현재 런타임이 이름을 제공하지 않는다.
3. 프리셋 이름에서 `JCM`, `5150`, `Mesa`, `AC30` 등의 키워드를 찾는다.
4. 일치하지 않으면 `TONEX Black`을 표시한다.

따라서 프리셋 19 문제는 개별 이미지 파일 손상이 아니라 자동 매칭 입력 데이터가 없는 구조적 문제다.

## 목표 구조

이미지는 다음 우선순위로 결정한다.

1. **사용자 수동 선택**: 프리셋별 Web 설정을 최우선으로 보존한다.
2. **실제 Tone Model 메타데이터**: TONEX 응답에서 얻은 모델명·제조사·기기 종류를 정규화해 매칭한다.
3. **프리셋 이름 추론**: 메타데이터가 없는 구형 펌웨어나 불완전 응답의 보조 수단으로만 사용한다.
4. **안전한 중립 이미지**: 검은 이미지 대신 식별 가능한 중립 TONEX 이미지를 표시하고 Web에 `자동 매칭 정보 없음`을 명시한다.

## 구현 단계

### 1. 통신 데이터 수집

- 프리셋 상세 응답의 원본 payload에서 사람이 읽을 수 있는 문자열 영역과 고정 필드를 기록한다.
- TONEX Editor에서 Tone Model만 바꾼 두 프리셋을 비교해 모델명 또는 모델 ID 필드를 확정한다.
- 프리셋 이름과 모델 이름을 혼동하지 않도록 별도 타입으로 파싱한다.

### 2. 도메인 모델 추가

- 런타임에 프리셋별 `ToneModelMetadata` 캐시를 둔다.
- 최소 필드는 `model_name`, 선택적으로 `manufacturer`, `category`, `model_id`를 사용한다.
- 새로운 프리셋 동기화가 완료될 때만 메타데이터와 파라미터를 함께 커밋해 이전 프리셋 이미지가 잠깐 보이는 현상을 방지한다.

### 3. 매칭 규칙 개선

- ASCII 대소문자뿐 아니라 공백, 하이픈, 점을 제거한 정규화 문자열을 사용한다.
- 긴 고유 키워드를 먼저 검사해 `Mark V`가 일반 `Marshall` 규칙 등에 잘못 잡히지 않게 한다.
- 매칭 테이블은 코드와 테스트에서 동일한 단일 데이터 원본을 사용한다.
- 매칭 결과에 `Manual`, `ToneModelMetadata`, `PresetName`, `Fallback` 근거를 유지한다.

### 4. 실패 UX 개선

- 매칭 실패를 검은 빈 영역처럼 표현하지 않는다.
- 보드에는 대비가 확보된 중립 이미지 또는 간결한 `TONE MODEL` 플레이스홀더를 표시한다.
- Web에는 `자동 매칭 정보 없음`과 수동 이미지 선택 기능을 함께 제공한다.

## 검증 기준

- 20개 프리셋 모두에서 빈 이미지가 나타나지 않는다.
- 프리셋 이름이 임의의 이름이어도 Tone Model 메타데이터만으로 올바른 계열이 선택된다.
- 모델명을 바꾸면 보드와 Web 이미지가 같은 프레임 상태에서 함께 바뀐다.
- 빠른 프리셋 변경 중 이전 이미지가 새 프리셋에 섞이지 않는다.
- 메타데이터가 없는 응답에서도 프리셋 이름 추론 또는 중립 이미지로 안전하게 동작한다.
- 사용자가 수동 선택한 이미지는 자동 매칭 결과보다 항상 우선한다.

## 하드웨어 검증에 필요한 자료

정확한 Tone Model 필드 위치를 확정하려면 TONEX ONE이 연결된 상태에서 프리셋 상세 응답을 한 차례 캡처해야 한다. 가장 신뢰도 높은 비교 방법은 동일한 프리셋 이름과 파라미터를 유지하고 Tone Model만 두 종류로 바꾼 뒤 두 응답을 비교하는 것이다. 필드가 확정되기 전에는 프리셋 19만 예외 처리하거나 이름을 하드코딩하지 않는다.
